01
System architecture

Three machines. One externally enforced release.

The NVFlare provisioning node creates the protected workload. An independent trust domain owns key release. The adversarial CoCo operator owns the cluster—but never the plaintext or release authority.

WORKLOAD AUTHORITY

NVFlare provisioning node

  • Builds and tests the plaintext image
  • Signs the immutable OCI digest
  • Encrypts layers with a fresh release key
  • Pushes only ciphertext to the registry
  • Generates strict Agent policy + measured InitData
  • Defines release authorization and Pod YAML

02
Measurement and attestation

Trusted reference meets live evidence at one equality gate.

The authoritative SNP measurement comes from a challenge-bound AMD-signed report. The secure-services trust domain authenticates that reference, then compares every live guest against it before KBS considers workload-specific release policy.

1 · Establish the trusted reference

03
Threat analysis

What the CoCo owner can attack—and why it fails.

Each useful modification breaks at least one independent binding. The design protects confidentiality and launch integrity; it intentionally does not guarantee availability.
