Status vocabulary:

- **V**: verified locally by the tests and revision recorded in the evidence
  section. This is limited to the named application, transport and environment.
- **U**: supported execution path, not qualified here. Export/runtime admission
  alone does not prove numerical, state, filter or environment compatibility.
- **M**: missing implementation/integration, with explicit rejection where stated.
  Required FedAvg cases remain release gaps.
- **J**: intentionally job lifetime in this delivery scope; retain resident
  regressions. Task conversion is not required for every non-FedAvg family.

`API` below means the exact `ClientAPIExecutor`, generated by `ScriptRunner`,
with `execution_mode="in_process"`. Its CPU task backend is Process. For every
API row, external-process task launch is **M** (rejected), while Attach and
required job-long trainer sessions are **J**. `launch_once` does not make these
contracts interchangeable. The common recipe configuration is
`recipe.add_client_config({"execution_lifetime": "task"})`; only some constructors
expose it too. `set_execution_lifetime()` belongs to FedJob, not Recipe. The
historical plan's Recipe setter is not present at this head.
No server workflow or executor substitution is needed for supported API rows.

## Contracts reused and slice selection

P4 directly constructs the authorized executor and invokes initialize, execute,
finalize. It does not implement a generic component graph/event dispatcher or a
per-task guardian. Do not infer worker support from the recipe's common base.

Client API scripts receive `flare.system_info()["task_checkpoint"]`: an isolated
`input` of the last locally committed opaque file (None initially) and a pending
`output`. The application uses native serialization. Immutable completion binds
the candidate to the result; CJ promotes after settlement, validation and replay.
Local promotion is not server receipt or algorithm acceptance. The next worker
gets local state; the server still provides the next global model. Retry of a
saved result does not rerun training. The historical design's declared-state
framework and automatic component placement are not current contracts.

The selected small slice is **PyTorch FedOpt with in-process clients on CPU
Process**: expose the existing lifetime configuration in its constructor, register
its framework/persistor/locator metadata for the global-evaluation helper, and qualify
DIFF exchange with multi-round server momentum/scheduler continuity. Reuse the
already checkpoint-aware hello-pt client for paired stateful training and
global-only evaluation. SCAFFOLD, local submit-model, Lightning restoration,
external task trainers, launchers, GPU admission and crash cleanup stay explicit
gaps. This is not completion of flag-only compatibility for all FedAvg scripts.

## Constructor API extension

The same constructor option is now exposed by five additional recipes:

- `NumpyFedAvgRecipe` (`fedavg-numpy`)
- `SklearnFedAvgRecipe` (`fedavg-sklearn`)
- `KMeansFedAvgRecipe` (`kmeans-sklearn`)
- `SVMFedAvgRecipe` (`svm-sklearn`)
- PyTorch `FedCERecipe` (`fedce-pt`)

All five already export the common CPU in-process task configuration through
`recipe.add_client_config()`. Their constructors now forward
`execution_lifetime="job"|"task"` to that existing path, and the generated CLI
catalog exposes the option. Job lifetime remains the default, including the
existing implicit job lifetime in format-version-2 client configs. No algorithm,
server workflow, executor or application-state implementation changes.

The new constructor/export tests compare each explicit task constructor with
the existing common-config selection. They require unchanged server/algorithm
configuration, the original default-job client config apart from task lifetime
and format version, valid task admission, invalid-lifetime rejection and
unchanged external-process rejection. Catalog tests cover all five options.
Together with the existing six FedOpt checks, 26 focused checks passed with no
skips. Adjacent FedAvg/FedOpt/FedCE/sklearn, task-contract, evaluation-helper and
CLI regressions passed 316 cases, with six TensorFlow cases skipped because
TensorFlow is unavailable. The expanded revision also passed the full Python style wrapper; notebook
formatting was skipped because Black's Jupyter dependencies are absent.

These are API/export checks. They do not qualify the five algorithms' numerical
behavior, arbitrary training scripts, estimator history, FedCE client state or
native checkpoint integration. Their baseline numerical/application statuses
in the matrix remain U. PyTorch FedAvg and FedProx already expose this option;
TensorFlow and HE integrations require their own framework/filter qualification.
